## Тестовое задание на DRF
### Описание 
Кастомизированную модель пользователя RewardedUser с дополнительным полем coins, которое можно доступно в административной панели. 

Отдельный endpoint для получения данных пользователя:

`GET api/profile/` - Требует аутентификации. Возвращает username, email и coins данного пользователя.

JWT авторизация со следующими endpoint'ами:

`POST /api/token/` — Для получения access/refresh токенов;

`POST /api/token/refresh/` — Для обновления токенов;

`POST /api/token/verify/` - Для валидации токенов.

Модели ScheduledReward и RewardLog. ScheduledReward требует будущую даты в поле execute_at. При создании ScheduledReward при помощи Django сигналов создается Celery задача, которая в назначенное время добавляет coins указанному пользователю и создает объект RewardLog. ScheduledReward можно создавать в административной панели, RewardLog можно только просматривать.

Отдельный endpoint для просмотра наград выданных пользователю.

`GET /api/rewards/` - Требует аутентификации. Выводит список RewardLog для запрошивающего пользователя.

Отдельный endpoint с ограничением раз в день на пользователя при помощи throttling.

`POST /api/rewards/request/` - Требует аутентификации. Создает новый ScheduledReward, который дает пользователю запрошенный amount через 5 минут.

### Запуск 

Запускается через docker-compose, который сразу включает для себя образы для PostgreSQL, Redis, Celery и самого приложения. Требуется .env файл с 3 параметрами - POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD. Docker сам создаст и проведет нужные миграции.

`docker-compose up --build`

Все должно запуститься. После этого последний шаг необходимый для работы - создание первого пользователя. Для этого можно просто в контейнере Django приложения создать супер пользователя:

`python manage.py createsuperuser`

После этого можно будет пользоваться административной панелью, создавать новых пользователей и награды. Endpoint'ы также доступны в браузере как BrowseableAPI.
